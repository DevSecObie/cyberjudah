It fits every measurement up to 08:30 UTC: the 06:40 UTC routine run on CYB-283 (continuation `b85dc2fb`) and the couriers it created ([CYB-284](/CYB/issues/CYB-284), [CYB-285](/CYB/issues/CYB-285), [CYB-291](/CYB/issues/CYB-291): origin `b85dc2fb`) work; CYB-157 (origin null, continuation `13cee27d`) and CYB-243 (origin `c6b177a1`) fail; the CEO's runs on CYB-3 at 08:30, 15:40, 18:30 and 19:30 UTC had none. So the context is a strong predictor, not the whole rule, and nobody promises a PR on the strength of an issue's context alone. **What follows, in order of certainty:** (1) the reliable test is per run: `gh api user` through the launcher on the exact issue, at the start of the run, before any promise of a PR; (2) an issue that needs git is created only from a run that has just passed that test, because a child issue appears to inherit the creating run's context; (3) widening the GitHub connection has not revived an existing thread, so old threads are treated as having no identity until a run on them proves otherwise. **Standing rule:** no seat opens another "GitHub identity unavailable" escalation.
