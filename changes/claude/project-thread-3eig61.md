- Class broadcast starts: data/sources/class-broadcasts.json has not gained a row since the hand backfill of 2026-10-08. The harvest looked each class up on its YouTube watch page and, when the page came back blocked or without broadcast details, printed only "broadcast start unconfirmed" and moved on; every class since then went that way.
- scripts/history/broadcasts.py now says why each class was not recorded (page refused with its HTTP error, a sign-in or bot check, no player data, not a livestream, still live, and so on) and the harvest log ends with a count of each reason.
- When the page gives no start, it asks yt-dlp (YouTube's player API, the same liveBroadcastDetails start), with a cookies file when one is given. A start more than a day from the class's date is refused. After five lookups in a row that YouTube refuses, the run stops asking and says so.
- New manual workflow "Backfill class broadcast starts" (broadcasts-backfill.yml) records the missing starts for dated classes, up to the number of lookups asked, with the YOUTUBE_COOKIES secret the audio fallback already uses; it commits what it found and fails when YouTube refused every lookup. `python3 scripts/history/broadcasts.py --since YYYY-MM-DD --tries N` does the same locally.
